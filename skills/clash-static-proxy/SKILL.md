# Clash 静态住宅代理

用中文执行。用户提供配置即授权完成本次节点配置、备份和重载；信息齐全时直接做。只缺协议且无法从输入推断时询问协议，不把 HTTP 静默当 SOCKS5。不自动切换现有业务组的选中项，不自动购买服务或测试外部网站。

## 输入与默认行为

- 接受 Clash 节点 YAML、代理 URL 或 IP/域名、端口、用户名、密码；URL 凭据需正确解码，端口必须是 1–65535 整数。无认证节点也支持。
- 名称优先沿用用户指定值；未指定时用 `住宅代理-<server>-<port>`。同名且同类型视为更新；与其他用途节点重名时先澄清。
- 默认添加到**当前启用订阅的全部普通代理组**，包括「🚀 节点选择」、ChatGPT、Claude、Gemini 等。用户指定部分组时以指定范围为准；本技能 helper 只实现默认全组模式，限定范围需调整后验证。
- 默认链式代理，独立上游组叫 `🔗 <节点名> 上游`。上游优先沿用用户指定的有效物理节点，否则沿用「🚀 节点选择」当前选中的有效物理节点。组名不是物理节点；必要时解析当前选择链。没有有效上游时询问，不能擅自改直连。
- 用户明确要求直连时移除该节点的 `dialer-proxy`，不新建上游组。
- 用户明确指定文件时以该文件为目标，但先指出与当前订阅是否一致；不偷偷切换订阅。非当前订阅只持久化和校验，不重载为当前配置。

## 1. 定位真实目标（先只读）

### UDP 配置

- SOCKS5 节点默认写入 `udp: true`（包括 Todaylab）；用户显式指定 `udp: false` 时保留，HTTP 节点不自动添加此字段。这只启用客户端 UDP 能力，不证明服务端或上游链路支持 UDP 转发。
- 仅修改现有节点 UDP 参数时，保持组成员、上游、规则及选中项；同步当前运行配置、用户指定订阅中的节点、`option.proxies` 及增强脚本里的受管理节点，防止重新生成后丢失。不要扩展到其他订阅。
- 热重载后用 `GET /proxies` 核验目标节点的 `udp` 返回值。规则集靠前但 UDP 请求仍落到后续规则时，检查节点 UDP 能力；Mihomo 会跳过不支持 UDP 的代理继续匹配，提前域名规则不能解决。
- 服务模式管道与路径限制的处理见 [执行说明](references/operations.md#服务模式下的重载)。

Windows 常见配置目录：`%APPDATA%/io.github.clash-verge-rev.clash-verge-rev`。

1. 解析 `profiles.yaml`，用 `current` 查找 `items[].uid`，取得 `file` 与 `option.script/proxies/groups/merge` 对应文件。**UID 不要写死**。
2. 解析当前订阅源、相关增强文件和 `clash-verge.yaml`，只输出脱敏摘要：订阅名、组名、节点是否存在、上游关系。大文件不要全部打印。
3. 从运行配置读 `external-controller-pipe`、`external-controller` 和 `secret`，访问本地 Mihomo `GET /proxies`，记录各组的 `now` 和成员，确认 UI 所见确实来自这个配置。优先使用命名管道；HTTP 仅允许本地回环地址，密钥只放请求头。
4. 检查目标目录的既有指令。找到 Mihomo 可执行文件（可从 Clash 安装目录查找 `verge-mihomo.exe`），不要把某台机器上的绝对路径作为通用前提。

曾发生的实际问题：用户给的是 IPLC 文件，但 UI 用的是 WgetCloud，后者的组名是「🤖 ChatGPT」，前者是「🧲 OpenAI」。磁盘文件修改成功不等于 UI 生效。

## 加密 DNS 分流

用户要求配置加密 DNS、修复 DNS 泄漏或参考另一订阅的 DNS 时，先读 [加密 DNS 分流](references/encrypted-dns.md)。默认国内域名使用国内 DoH 直连，其他域名经明确的有效代理查询海外 DoH；引导解析也使用 IP 地址形式的加密 DNS。必须保留机场专用的节点解析器，避免把节点域名交给公共 DNS 后误判节点失效。仅修改目标订阅并备份、校验、持久化、热重载；不自动切换业务组选择。仅配置静态节点时保留现有 DNS，除非用户同时要求调整。

## 2. 构造持久化变更

使用 [scripts/transform.cjs](scripts/transform.cjs) 的 `transform(config, entries)` 做确定性变换，`buildEnhancer(existingScript, entries)` 生成保留既有 `main` 的增强脚本。参数和示例见 [references/operations.md](references/operations.md)。helper 不负责读写真实配置或网络请求。

- 不将凭据写入技能仓库、日志、Git 或最终回复。只写用户的私有 Clash 配置目录；临时文件放私有临时目录，完成后删除本次临时文件。备份也含凭据，留在 Clash 私有目录内。
- 读取并保留现有增强逻辑。生成的 wrapper 先调用原有 `main`，再应用静态节点；重复执行更新自己的受管理区块，并保留其他静态节点。
- 如果已有其他手写 Todaylab/住宅节点逻辑，检查其上游与组引用；需要迁移时只替换已确认属于该节点的逻辑，不删除无关脚本。
- 若同名节点也出现在 `option.proxies` 的 prepend/append 中，同步其连接参数和上游，防止阶段顺序不同导致旧参数覆盖。检查 remove/delete 规则和脚本执行顺序；不能假设单一文件决定结果。
- 缺少订阅专属 script 条目时，创建独立 script 文件并在 `profiles.yaml` 注册，绑定该订阅 `option.script`；保留其他字段。此时需要通过应用重新读取订阅元数据，不能只改内核运行文件便声称持久化已验证。
- 不直接把 Todaylab 放进它自己的 `dialer-proxy` 组。**要同时允许主选择组选择住宅节点，就把住宅节点的上游移到独立组。** 上游组只收不依赖任何 dialer-proxy 的物理代理，不收住宅节点自身或其他组。它是“全部组”的明确例外。
- 遇到 `relay` 组，不把节点追加为新的一跳；helper 会停止，需按用户实际路由意图单独处理。

## 3. 验证、落盘、生效

1. 先在内存或私有临时文件生成候选配置，YAML 解析并检查：节点唯一、引用存在、所有目标组恰好包含一次节点、上游不回指自身、路由规则与无关设置未改。
2. 用 `mihomo -t -d <配置目录> -f <候选配置>` 验证。失败时不写正式配置；不因失败更换用户的协议或凭据。
3. 再次确认 `profiles.yaml.current` 及待改文件未被用户/订阅更新并发改变；如改变，重新读取构造。为每个待改文件创建带时间戳且不覆盖已有文件的备份，再写增强文件和当前运行配置。文件写入一半失败时恢复本次已写文件。
4. 当前订阅通过本地控制 API `PUT /configs`，JSON `{ "path": "运行配置绝对路径" }` 热重载。保留已有业务组选择；新建上游组用 `PUT /proxies/<URL编码组名>` 设置为之前验证过的物理节点。
5. 再 `GET /proxies` 核验主选择组、ChatGPT 等目标组真实包含节点，上游不包含自身，当前业务选择保持。必要时恢复仍有效的旧选择。只报告实际完成的验证；Mihomo 配置校验不证明住宅 IP 联网成功。
6. 用原始订阅配置和相关增强步骤模拟重新生成，确认节点可持续注入；若无法确认应用的增强执行顺序，说明尚需应用重新生成后验证，不把仅内核重载当完整持久化验证。
7. 重载失败最多修复明确原因后重试一次；仍失败则恢复本次备份并尝试重载旧配置，报告失败和回滚结果。API 不可用时保存已验证的持久配置，明确说明需用户在 Clash 中重新加载，不声称运行中已生效。

最终简短说明目标订阅、节点名、加入哪些组、独立上游选择、备份与运行验证结果，不复述账号密码。仅创建或测试技能时不得改动用户的活动代理配置；用户同时明确要求修改实际 Clash 配置时，按对应授权范围执行。
